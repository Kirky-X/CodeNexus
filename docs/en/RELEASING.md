# 🚀 Release Reconciliation Checklist

> Verify each item before every release. Background: the skill docs once drifted to "28 subcommands / 8 languages",
> and the README once claimed "6 runnable examples" (actually 14) — the skill is the agent's first entry point,
> so stale numbers directly cause wrong calls, and a missing example index makes new examples undiscoverable.
> This checklist ensures **the code is the single source of truth and doc numbers are reconciled before release**.

## Reconciliation items (code → docs)

| # | Source of truth (count here) | Current baseline | Docs that must align | How to align |
|---|------------------------------|------------------|----------------------|--------------|
| 1 | CLI subcommand count: `grep -rn "cli = true" src/service/*.rs` (excluding `mod.rs` comment lines) | 37 registered subcommands (`codenexus mcp` is a main.rs string interception, not a registered subcommand) | `README.md` / `README_CN.md` "CLI Commands" section, `docs/en/USER_GUIDE.md`, `skill/SKILL.md`, `skill/references/commands.md` | Write the registered count as "37 subcommands"; lists that include the `mcp` serve mode say "37 + mcp", never a bare 38 |
| 2 | MCP tool count: `grep -rn 'tool_name = "' src/service/*.rs \| grep -v hook` | 10 (query/trace/impact/search/context/architecture/diagram/arch_diff/dead_code/detect_changes) | `README.md` / `README_CN.md` "MCP Integration" section, `docs/en/USER_GUIDE.md`, `docs/en/FAQ.md`, `skill/references/commands.md` | When adding an MCP tool, also update the `sdforge::mcp` tool-surface description |
| 3 | Language count: `grep -c '^lang-' Cargo.toml` | 22 (one `lang-*` feature per language) | `skill/SKILL.md`, the language table in `skill/references/appendix.md`, the feature table in `docs/en/USER_GUIDE.md` "Build presets and feature flags" | Extensions in the appendix language table follow `src/model/language.rs`; node types follow `NodeLabel::` in `src/parse/<lang>.rs` |
| 4 | Example count: `grep -c '\[\[bin\]\]' examples/Cargo.toml` | 14 | `docs/en/USER_GUIDE.md` "Examples" section (table + run-all loop) | A new example bin must update the table and for loop in the `docs/en/USER_GUIDE.md` "Examples" section in the same PR |
| 5 | Command flags: the `#[forge]` CLI wrapper signatures in `src/service/<cmd>.rs` | — | The matching entries in `skill/references/commands.md` | New commands or changed signatures must update the Options list and sentinel defaults in commands.md (`src/main.rs` `SENTINEL_DEFAULTS`) |
| 6 | Advisory ignore list | `deny.toml` (single source of truth) | `.cargo/audit.toml` (synced mirror; cargo-audit only reads that path or `~/.cargo/audit.toml`, a same-named file at the repo root is not loaded); the CI audit-check ignore list is generated by grepping deny.toml | Only edit deny.toml and update the review date, then manually sync `.cargo/audit.toml`; comments may only contain RUSTSEC IDs that are being ignored |
| 7 | Base-library dependency policy | `Cargo.toml` (base libraries such as trait-kit/sdforge/oxcache/inklog/limiteron/lbug/vecboost must all use crates.io version reqs, **no** path deps / `[patch.crates-io]` — vecboost returned to crates.io as of 0.3.0-rc.2, and the temporary git-patch arrangement ended when upstream rc.2 shipped) | `Cargo.lock` (refreshed and committed in the same commit) | When upgrading base libraries, sync the version reqs to the latest published versions and refresh the lockfile; never reintroduce cross-repo path/patch entries (use temporary `cargo patch`-style measures for local integration testing only, never committed); the patch guard in release.yml stays as a permanent safety net (it rejects a crates.io publish while a patch is active) |
| 8 | Behavior changes since the last tag: `git log --oneline $(git describe --tags --abbrev=0)..HEAD` (focus on feat/fix/perf) | — | The `## [Unreleased]` section of `docs/en/CHANGELOG.md` | Behavior fixes/additions/changes after a tag must be logged under `[Unreleased]` first; at release time they merge wholesale into the new version section, leaving no empty sections |

## Mechanical checks (run before release)

```bash
# 1. Command count (should be 37)
grep -rn "cli = true" src/service/*.rs | grep -v "//" | wc -l
# 2. MCP tool count (should be 10)
grep -rn 'tool_name = "' src/service/*.rs | grep -v hook | wc -l
# 3. Language count (should be 22)
grep -c '^lang-' Cargo.toml
# 4. Example count (should be 14)
grep -c '\[\[bin\]\]' examples/Cargo.toml
# 5. Stale numbers that must not appear in docs
grep -rn "28 subcommand\|8 languages\|Supported languages (8)\|6 个可运行示例\|6 runnable" README.md README_CN.md docs/ skill/ && echo "发现过期数字！" || echo "OK"

# 6. Unreleased entry (must exist if feat/fix/perf commits exist after the last tag)
if git log --oneline "$(git describe --tags --abbrev=0)"..HEAD --grep='^\(feat\|fix\|perf\)' | grep -q .; then
  grep -q '^## \[Unreleased\]' docs/en/CHANGELOG.md && echo "OK" || echo "缺少 [Unreleased] 登记！"
else
  echo "OK（无行为变更）"
fi
```

> The expected values for items 1–4 grow with each release; **always trust the output of the source-of-truth commands in the reconciliation table**, do not backfill the numbers in this file.
