## [0.4.0] — 2026-11-14

### Changed

- **refactor(cli): the standalone `codenexus-verify` binary folds into the main CLI as the `verify` subcommand** — the former `[[bin]] codenexus-verify` (a custom path form in `tools/verification/src/main.rs`) is deleted, with the implementation moved wholesale into the library-side `src/verify/` (five modules: orchestrator + statistics / gitnexus client / query comparison / report / type mapping); the entry point registers via the sdforge inventory (`codenexus verify <single|batch|fetch-samples>`). Functionally equivalent: index bootstrapping (child-process `cargo run --bin codenexus -- index --release`), opening `./codenexus.lbug` directly, unchanged artifact paths (`tools/verification/results/`, `samples.json`, `type_map.json`, `queries/*.cql`); `--only` item filtering switches to a single comma-separated argument (`--only a,b`), stderr progress output and error semantics unchanged; when the host process is `verify` the Kit build is skipped (same policy as `webui`, avoiding lock contention with the child-process indexing). Data files stay in `tools/verification/` untouched.

### Added

- **feat(cli): wiring for `context --budget` and `daemon --notify-impact`** — `context` gains `--budget <N>` (`Option<usize>`; omitting it disables truncation, `0` is a parameter error with exit 2): results are truncated via `service::budget` with a `budget` receipt attached, and without a budget the output stays byte-for-byte identical. `daemon` gains `--notify-impact` (default false, also accepting `--notify_impact` and explicit `true`/`false`): when enabled it registers an `impact_observer` alert callback after each incremental index completes, and when disabled behavior is unchanged. This removes two "capability exists but unreachable from the CLI" gaps; README, README_EN, and USER_GUIDE parameter docs are synced.

- **feat(parse): Swift language parsing support** — new `lang-swift` feature (tree-sitter-swift 0.7) and `SwiftExtractor` (functions/methods, classes/structs/enums/actors, protocols, extensions, properties, constructors, type aliases, imports, calls); `full` preset language count 21→22; validated with indexing and graph queries against two real GitHub repos, apple/swift-argument-parser and Alamofire.

### Fixed

- **docs: release reconciliation — subcommand and MCP tool count calibration (37→39 / 10→11)** — using the binary's actual registration surface (`codenexus --help`: 39 subcommands plus the `mcp` serve mode) as the source of truth: the `verify` subcommand and the dual CLI/MCP registration of `source` had previously been missing from the doc inventories. README/README_EN command groups add `verify` and update the count 38→39; the SKILL.md quick table adds `source`/`verify` rows and adds `source` to the `mcp` row's tool list (11 tools); commands.md coverage wording becomes "36 of 39 (`ci`/`source`/`verify` not covered)"; USER_GUIDE (39 subcommands / 11 tools) and FAQ (11 tools) synced.

- **fix(storage): fix the four platform gaps that made `codenexus index` always fail on Windows** — LadybugDB's write lock on Windows is a `LockFileEx` byte-range lock (owned by the file handle), so opening a second write handle in the same process always hits `ERROR_LOCK_VIOLATION (33)`, whereas Linux's `fcntl` lock is per-process — this repo has no Windows CI, so the gap never surfaced. ① `StorageConnection` now holds `Arc<Database>` with a process-level weak-reference handle cache (key = canonical path + read/write mode), reusing one handle per path per process; `import` explicitly invalidates cache entries after replacing the library file, so a stale handle is never handed to the re-index pipeline. ② Node ids embed Windows drive-letter colons (`C:.Users...`), and LadybugDB treats `C` as a file type and reports `Cannot load from file type C`; the CSV temp file name sanitization charset gains `:`. ③ `probe_available_disk_space` compared a verbatim-prefix (`\\?\`) canonical path against `sysinfo` mount points, which on Windows is always 0, degrading `max_db_size` to the 64 GiB fallback; now the verbatim prefix is stripped and matching is done by string prefix. ④ Two Unix-only tests (`signal_hook::consts::SIGUSR1` and `std::os::unix::fs::symlink`) gain `#[cfg(unix)]`; without this the test suite did not even compile on Windows. Verification: indexing this repo's 321 files / 21299 nodes / 113058 edges succeeds on Windows (previously `database is locked` exited 2 directly); when two processes write one DB, the later writer exits 2 and the DB is not corrupted; `cargo test --lib` Linux 4726 passed / 0 failed, clippy 0 warnings; the Windows failure set matches the clean HEAD baseline (615 → 25, all pre-existing Windows gaps, 0 new).

- **fix(index): edge integrity gate before load, eliminating DQ-004 orphan edges and fixing three edge-building defects** — `LoadPhase` adds `enforce_edge_integrity` before the write transaction: missing edges with `#` in the source are re-homed to the parent entity after stripping `#` (repair); global dedup across the id string (fixing `COPY FROM` primary-key conflicts); edges whose endpoints are absent from graph∪DB are dropped (per-edge `debug!` + aggregated `warn`). Collateral fixes: in `resolve/imports.rs`, the `(relative path, file_id)` return of `FilePathIndex::lookup` was destructured swapped, so the source of IMPORTS/REEXPORTS/DEPENDS_ON edges was always a relative path matching no node, and the target resolver treated the file_uuid as a relative path (in-project imports misjudged as external dependencies); `LoadPhase` skips re-inserting survivors among nodes without a `filePath` label (e.g. `ExternalPackage`), fixing the incremental / hot `--force` primary-key-conflict crash rollback. Correctness semantics: survivor domain = old nodes − rows pending path deletion ∪ new graph nodes; `show_tables` preflight replaces error-substring swallowing; NULL `filePath` rows count as not-surviving. Performance: fresh full indexing +10.4% (the irreducible cost of fixing two real crashes). Verification: `cargo test --lib` 4702 passed (16 new tests), clippy 0 warnings.

- **fix(ci): coverage job installs cargo-llvm-cov** — `taiki-e/install-action` was missing the `tool` input so nothing was installed, and the coverage job kept failing with `no such command: llvm-cov`; added `tool: cargo-llvm-cov` following the fuzz-smoke job's pattern. The identical local pre-push command measures line coverage ≥95%.

- **fix(embed): test assertions switch to `kind()` static labels, clearing CodeQL cleartext-logging alerts** — `EmbedError` gains `kind()` (returns a `&'static str` variant label, zero-allocation, no wildcard arm); the three assert messages in `module.rs` / `bootstrap.rs` and the same-class downstream spots in `client.rs` no longer format the full `embed()` return value; `bootstrap.rs` assertions switch to a locale-independent model-path payload and join the i18n serialization group (fixing guaranteed failure under zh locale / isolated runs). Verification: `cargo test --lib` 4691 passed (including zh/en/no-locale three states).

### Changed

- **feat(sdk)【BREAKING】Nexus SDK facade lands + LSP registry becomes capability-based (trait-kit-sdk-facade)** — ①`src/sdk` (`#[doc(hidden)]` internal form): `Nexus` holds `Arc<AsyncKit<AsyncReady>>`, with `open(full config)/from_kit/from_runtime/raw_kit/shutdown` (in-place await of !Send futures) + 11 capability accessors (storage/parser/extractor/indexer/resolver/query/trace/daemon/embed/cache/lsp), signatures free of bare trait-kit types; `NexusError` switches to its own 11-variant mirror (`kind()` classification + FTL-localized Display `sdk-error-*`, `From<KitError>` per variant, reverse mapping to `CodeNexusError` preserving exit codes). ②`runtime::nexus()` single point: 44 `kit()` global fetches migrate to `&Nexus` parameters. ③LSP registry becomes capability-based: `LspRegistry` (factory semantics; select materializes a new instance each time) + `MAX_LSP_PROVIDERS` folded into the module; uncovered extensions now error explicitly (previously an implicit fallback to rust-analyzer). ④T012 instance isolation: the global DB_KEY is removed; DB identity follows the Nexus instance (`Nexus::db_key`); `#[cached]` keys become `cypher:{db_path}.g{gen}:{cypher}`, and index invalidation switches to a generation bump (`invalidate_namespace` scoped precisely to the instance ns); **the index-invalidation chain is now wired into production** (IndexerModule declares the cache dependency + `with_cache` wiring + e2e test). ⑤CI adds the trait-kit feature-surface snapshot gate (`docs/ci/trait-kit-feature-face.txt`). Verification: lib 4874/0, bins 54/0, minimal combination compiles, clippy 0 warnings.

- **fix(storage)【BREAKING】edge primary-key id boundaries switch to a length-prefixed format; existing databases must re-index with `codenexus index --force`** — v1's `{source}_{target}_{type}_{start_line}` joins components directly with `_`, but qualified-name segments themselves contain `_`, so `("a_b","c")` and `("a","b_c")` render the same id string (CSV writing dedups by the tuple, both rows land → `COPY FROM` primary-key conflict aborts the whole index); also `None` and `Some(0)` start lines both render as `…_0`. v2 uses `{source_len}|{source}|{target_len}|{target}|{type}|{line}` (missing line recorded as `-`); the two collision pairs are pinned by behavior tests (`edge_id_is_unambiguous_across_underscore_boundaries` / `edge_id_distinguishes_missing_from_zero_start_line`), and a new guard test locks `EdgeType` DB names to never contain the `|` separator. `write_edges_csv_stream`'s dedup key switches `start_line` to `Option<u32>` in sync (v1's `unwrap_or(0)` silently deduplicated legitimate line-0 edges). **Upgrade note: old-format ids do not match the new format; existing projects must re-index fully with `codenexus index --force`** — otherwise edge pre-deletion queries for old-format persisted rows by new ids, misses them, and re-derived edges conflict with their leftover rows.

- **fix(index)【BREAKING·same as above】incremental edge pre-deletion becomes "the set not covered by orphan cleanup" + 500/chunk streaming** — `LoadPhase`'s edge pre-deletion no longer materializes all incoming edge ids (≈125B/edge, ~60MB peak at 500k edges); it now streams collection in 500/chunk and only pre-deletes edges **not covered by path-key deletion** (endpoints are survivors, or neither endpoint is in the pending-delete path set — the latter being exactly the two-unchanged-files edges restored by enrichment); edges already covered by path-key deletion (an endpoint node deleted in this run) are handed back to the orphan-cleanup path, eliminating the pointless amplification of write-transaction lock hold time. The `edges_pre_deleted` count semantics narrow accordingly to "pre-deletion candidates". Pre-deletion also becomes **unconditional**: when edges form between `filePath`-less labels (e.g. `ExternalPackage`), no path-key deletion can reach them, and v1's skip-pre-deletion shortcut for full runs is broken by that case (guard test `pre_delete_covers_edges_between_column_less_nodes` mechanizes this invariant). Collateral fix for the id-sanitization fork: CSV writing applies `sanitize_for_ladybugdb` to id columns (`\`→`/`, `"`→`'`, newline/tab→space), but v1's pre-deletion/dedup gate queried the DB with raw ids — path segments containing those characters forked the lookup key from the persisted key, so pre-deletion never hit; `edge_id` is now sanitized uniformly at generation (guard test `edge_id_matches_the_persisted_id_column_byte_for_byte` locks delete-key == write-key).

- **fix(source)【BREAKING·same as above】source read path merges the single whole-file read + defense-in-depth for degenerate roots** — ①`validate_freshness` changes its signature to return `FreshSource` (the file bytes read once for the hash): the hash is computed over the bytes (index-time BLAKE3, oversized pre-check), and slicing reuses those bytes — one call now does at most one whole-file read + one file canonicalize (root canonicalize counted separately), eliminating the previous 2× whole-file reads + 1× duplicate canonicalize; behavior equivalence verified by the full existing source test suite and end-to-end CLI reads. ②`project_root` rejects degenerate roots: when rootPath is the filesystem root, `starts_with` is always true and traversal protection fails completely (only possible from a tampered/corrupt index DB) — the check uses "no parent directory after canonicalization" rather than `== "/"` (Windows drive roots `C:\` and UNC share roots likewise have no parent), adding `StaleReason::InvalidProjectRoot` with error text pointing at `codenexus index`. ③The slice-read path (`read_source_file_canonical`) pre-checks `MAX_FILE_SIZE` (same constant as the hash path) — analysis-side callers have no hash-phase backstop, so oversized files are rejected before reading (sparse-file behavior test pinned).

- **fix(test) log capture helper removes per-layer filtering and rebuilds the interest cache within the window, fixing flaky `log_003` subset runs** — `capture_tracing_debug` previously attached a per-layer filter via `with_filter(LevelFilter::DEBUG)`: tracing computes per-callsite `Interest` through a **thread-local** `FilterState` for per-layer filters, and rebuilds under concurrent tests could pollute it to `never` (callsites below the filter level deposit `never`, and later rebuilds pick it up and attribute it to other callsites) — once a callsite caches `never`, events are skipped at the macro layer and never reach any subscriber, so captures running on other threads silently lose events (measured: full suite green, `cargo test --lib -- service::source cypher` subset ~50% failures, probes confirmed events never reached the subscriber stack while same-window direct events did). Fix: the capture subscriber no longer attaches a per-layer filter (the registry answers `Interest::always` directly, no pollutable thread-local state; assertions use `.contains`, so levels of multiple captures are harmless), and within the capture window a one-shot `Dispatch::new` forcibly rebuilds the process-level callsite interest cache, re-anchoring the cache to the current capture. The same capture helper in `parse/parallel` is fixed in sync. Verification: `cargo test --lib -- service::source cypher` 10 consecutive runs with 0 failures (previously ~5/10 failures).

- **docs(security): vulnerability reporting makes GitHub Security Advisories the primary channel** — the security-advisory link uniformly points to the verified `/security/policy` page, email demoted to a fallback only when the primary channel is unavailable; unreachable contact emails removed, unified to the MX-verified `Kirky-X@outlook.com`; vague team attribution unified to the specific individual Kirky.X; the channel order in CODE_OF_CONDUCT / FAQ corrected.

- **docs(readme): roadmap calibrates Web UI and graph visualization status** — the 📋 item "deep 3D graph-viewer integration still planned" becomes ✅: v0.4.0-rc.2 delivered the opt-in `webui` feature and the `codenexus webui [--port]` embedded service (frontend `graph-viewer/dist` embedded at compile time, loopback-only binding + `x-graph-token` + Host validation), plus `diagram`/`arch_diff` architecture HTML, semantic Delta, and snapshot integration (`--viewer_url`); future enhancements are more chart types and two-way diagram↔viewer interaction. README_EN synced with the `webui` feature-table row, subcommand notes, and roadmap entry.

- **docs(assets): main logo replaced with the new 1254×1254 square image, display size unified at 240** — `docs/assets/CodeNexus.png` content replaced with the new square image (reference path unchanged); the main logo display size in README.md / README_EN.md unified from 180/200 to 240, matching the workspace's other repos.

### Added

- **feat(webui): graph-viewer merged into the main binary (feature `webui` + `codenexus webui`)** — the standalone crate `codenexus-graph-server` is deleted; the HTTP backend moves into `src/viewer/` (routing/auth/Host validation/static assets), data access switches to `QueryFacade::new_read_only` + `cypher()` (reusing the already-JSON `QueryResult`, deleting the hand-written `value_to_json`), and i18n drops its mirror in favor of `crate::i18n`; the frontend `graph-viewer/dist` assets are embedded at compile time (rust-embed, excluding `*.lbug` fixtures; with dist missing, compilation still succeeds and shows the fallback guide page). The `webui` subcommand defaults to port 9800 with a security model item-for-item identical to the old server (loopback-only binding, `x-graph-token`, Host loopback validation, directory whitelist); `webui` builds no Kit, creates no empty DB, and contends for no locks. Also fixes `/api/trace`: the old relationship-type pattern query (`(a)-[r:TYPE*1..N]->(b)`) always hit a Binder error on this repo's single-table `CodeRelation` schema (and the edge table stores qualified names, so resolving by `n.name` always came up empty); replaced with per-hop expansion + dual name/qualifiedName resolution, response shape unchanged. Adds the `cn` alias binary (same `src/main.rs`, same CLI surface as `codenexus`).

- **feat(status): absorbs trait-kit `AsyncKit<Ready>::health_aggregate()` (health × report; not the string-form `health_json()`)** — with the trait-kit `report` feature enabled, `status` now samples health once via `health_aggregate()`: a new structured `kit_health_aggregate` (worst-of status + per-module detail), the old `kit_health` (name=status) derived from the same aggregate with unchanged semantics; and registers a Storage (plus Cache when `cache` is on) health checker in `build_kit` — previously the production path registered no checker at all, so the aggregate was always empty.

- **feat(logging): absorbs inklog per-target levels / the `RUST_LOG` directive set / runtime hot-tuning** — adds `src/logging.rs` (`#[doc(hidden)] pub mod logging`); CLI log initialization migrates from the builder chain to `InklogConfig` (each builder knob maps 1:1 to a config field; `target_levels` lacking a builder setter was the migration driver). `RUST_LOG` is no longer passed wholesale to `LoggerBuilder::level()` — both the directive form (`codenexus=debug,sqlx=warn`) and the empty string trigger builder validation failure and panic at `.expect("init inklog")`, i.e. the per-module filtering long documented in USER_GUIDE/.env.example was previously unavailable; now only the bare level is extracted from `RUST_LOG` as the global default (default `info`), and directives are appended to `EnvFilter` by inklog itself (precedence `RUST_LOG` > presets > global). New `CODENEXUS_LOG_TARGETS` (`target=level` comma-separated, invalid entries skipped with a stderr notice) feeds `target_levels` as per-module presets, remaining effective even under process managers that set `RUST_LOG=info`; `LoggerManager` changes from `mem::forget` to static ownership, adding `codenexus::logging::set_level(target, level)` for runtime hot-tuning (reload swap, no restart). 8 new tests cover level parsing, config mapping, directives landing in EnvFilter (`current_level_filter_string()` exact assertion), and hot-tune upsert/invalid-level invariants.

- **feat(logging): absorbs sdforge's declarative function-level structured logging `#[forge::log]` (`inklog` feature)** — the two CLI command entries `query` / `status` get the attribute (`#[forge::log(args, err_detail)]` / `#[forge::log(err_detail)]`; the attribute sits on the outer wrapper, and `#[forge(cli = true)]` registration and the clap flag surface still point at the logging wrapper): each call enters the existing inklog pipeline via the `log` facade, producing `fn_enter` (debug, `args` masked by DataMasker) and `fn_exit` (success at the configured level, a `Result`'s Err always at error, with `ok`/`duration_ms`/`err_detail`); the existing level knobs (`RUST_LOG` / `CODENEXUS_LOG_TARGETS` / `set_level`) work as usual. `sdforge/inklog` was already enabled explicitly by the `cli`/`mcp` features (no new feature in `Cargo.toml`), and `log` is added only as a dev-dependency for test capture. Eliminates 4 DQ-002 warnings; downstream `context`/`rename`/`impact` symbol resolution is no longer ambiguous on the 4 collision sites.
- **fix(parse): DQ-004 orphan edge from Python nested functions** — CalNexus indexing reported 2 DQ-004 Orphan edge warnings where the source node existed but the target (`_strip_blank_ends`) did not. Root cause: Python nested `def` (def inside another def) was previously skipped entirely to align with gitnexus function counts (170 vs 280), but outer functions calling inner ones still emitted CALLS edges targeting non-existent nodes. Fix in `python.rs::extract_function`: nested functions are now extracted as Function nodes but marked `is_global = false` so they don't pollute the global symbol table, while still providing a target for CALLS edges. Eliminates 2 DQ-004 warnings; the `flush_section`/`flush_req` → `_strip_blank_ends` call chain is no longer broken.

### Changed

- **Migrated all components to the `trait-kit` unified registry**. The in-tree `src/kit/shim.rs` fallback was removed once every module used `build_kit`. `trait-kit` is now a hard dependency.
- **Broke the `parse` ↔ `resolve` circular dependency** by introducing the `src/ir/` module for shared intermediate representations (R-3).
- **Reduced the `visit_node` parameter count** by introducing a `VisitContext` carried across the 5 extractors (R-1).
- **Calls edge confidence range** adjusted to 0.80–0.95 to better reflect extraction certainty.
- **File path normalization** and `Parameter` node persistence added to the index pipeline.
- **Release profile** tuned for maximum performance and smallest binary: `opt-level = 3`, fat LTO, single codegen unit, `panic = abort`, `strip = true`.

### Fixed

- **FQN collision (P0)** — fully qualified names now retain the full file name and use a disambiguator suffix to avoid cross-file collisions.
- **Architectural orphan edges (P0-1)** — parser edge endpoint IDs are now synced so edges never reference missing nodes.
- **CSV header ghost nodes (P2-1 / DQ-005)** — `COPY FROM` now uses the `HEADER` option so CSV header rows are not ingested as phantom nodes.
- **C `#define` macro missed extraction (P1)** — `preproc_def` / `preproc_function_def` nodes are now extracted.
- **C anonymous `typedef struct` and header-file function declarations** are now extracted (P1-1 / P1-2).
- **Rust `Module` missed extraction (P2-1)** — module nodes are now correctly emitted.
- **Python `Function` over-extraction (P2-5)** — false-positive function nodes are suppressed.
- **TypeScript `Const` / `Interface` / `Function` extraction bugs (P2)** — three correctness bugs in the TS extractor.
- **TypeScript anonymous `export default` function** missed extraction (P2-4).
- **`dedupe_qn` O(N²) → O(1)** — switched to a `HashSet` lookup (MED-002), eliminating a quadratic bottleneck during qualified-name deduplication.
- **CSV injection safety** — string escaping consolidated into the schema module and applied consistently across the Python and TypeScript extractors.
- **Daemon debounce and index-phase error handling** — file-watching events no longer crash the daemon on transient parse errors.
- **Exit code 4 for a corrupt DB** now surfaces correctly through the Kit error layer rather than being masked as a generic failure.
- **The `pattern_name` fallback in the Rust extractor** now only accepts valid identifiers, preventing garbage names from malformed patterns.

### Security

- **CSV injection hardening** — `escape_cypher_string` consolidated into the storage schema module; all string fields route through it before `COPY FROM`.
- **Database corruption detection** — corrupt LadybugDB files are detected at startup and reported with a distinct exit code (4) instead of being loaded into a half-valid state.
- **`.env` files ignored by default** in `.gitignore`, with an explicit `!.env.example` allow-list so the template is tracked but real secrets never are.
